> **一句话职责**：agent 命令面 + AppState-free 桥接——`commands/*` Tauri handlers + 各 bridge（db/tracking/session/graph/embedder/sidecar）+ harness 工具（submit/trace/start_operation），并扁平 re-export agent 栈（A3 删 golish-ai umbrella 后直接从实现 crate 暴露）。

- **类型**：目录模块（属于 crate [`golish-agent-app`](../golish-agent-app.md)）
- **路径**：`backend/crates/golish-agent-app/src/ai/`
- **状态**：✅ 已写卡

## 何时该读这张卡（给 AI 的触发提示）

- 加/改 agent Tauri command（`ai/commands/*`）、各 bridge（把 agent-kit 的 trait 接到 golish-db/graphiti/indexer/sidecar 实现）时

## 职责

agent 服务命令面宿主。`commands/` 是 Tauri handlers；各 `*_bridge` 把 `golish-agent-kit::db_traits` 等 trait 用具体基础设施（golish-db / graphiti / indexer / sidecar / embedder）实现并注入；harness 工具暴露 stage harness 给 agent。C7 由本层把 DB exact authorization reader、server-owned principal policy 与 local temporal graph source 组合成 `ContextPackProvider`，再经 bridge 注入 runtime。`ai/mod.rs` 还扁平 re-export agent 栈（替代已删的 `golish-ai` umbrella）。

## 注意事项 / 坑

- **C9 Reporting authority bridge**：`db_bridge/reporting.rs` 只读取 frozen scope、Cleanup closeout gate 与 final-sealed/non-invalidated StageHandoff canonical refs；不接 ContextPack/wiki/Graph fallback。`PgReportTruthPort` 的 build 使用单个 `REPEATABLE READ READ ONLY` snapshot，完整 source hash 同时覆盖 canonical row、edge membership、typed blocked decision（actor/reason/residual + exact decision evidence）以及每个被引用 `audit_log` evidence 的完整 body/run/role/org metadata；Cleanup truth 也在该 snapshot commit 前读取。CandidateAttempt source 明确排除可随 live inventory 删除而清空的 `target_live_id`，但保留 frozen target type/value/identity、plan/result/status/evidence 与 `row_version`，因此 FK 清理不会制造同版本异哈希。typed authority 在任何 report row 持久化前拒绝 missing/foreign-operation/sibling-org evidence，blocked residual 绝不引用 obligation-creation evidence。final publish 在一个 `REPEATABLE READ` 写事务内锁定 revision 与 mutable children/evidence，重跑 complete source query，并重验 stored claim/citation hash、evidence binding、validation attestation 与 Cleanup-owned closeout truth后才 CAS。TechniqueOutcome authority 可以是 legacy row ref，或 exact operation/org 的一个 Vuln `TechniqueOutcomeSet` ref；后者在同一 RR snapshot 重算并展开全部 row。最终 row/source 仍必须双向全等，missing/duplicate/drift/unsealed addition/unresolvable 任一情况 fail closed。
- **C9 Reporting IPC authorization**：`reporting_get_read_model/list_revisions/get_artifacts/build_read_model/finalize_revision` 在 report read/build/exists/confirmation 分支前统一调用 `authorize_reporting_scope`。它只接受 provider 返回的 `LocalDesktop` opaque principal，并从 DB 解析 exact operation→active project→sealed frozen org snapshot；unknown/foreign/retired/unsealed/mismatch/provider failure 全部对 IPC 收敛成同文案 `REPORT_FORBIDDEN`。授权同时冻结 project id、canonical path、path SHA、project row version 与 sealed snapshot id/hash 为 server-only witness；`PgReportTruthPort` 在 validated revision 持久化事务、`PgReportPublicationPort` 在 publish 事务内重新锁定并 exact compare authoritative operation/project/snapshot rows，rename/retire/rebind 不能利用 autocommit TOCTOU 落库或发布。后续 bundle 还必须与 authorized operation/project/snapshot/hash exact 相等，artifact root 与 finalizer principal 只能取 authorized context，不能回读 caller 字段。
- **C9 Reporting Gate bridge**：`db_bridge/reporting_gate.rs` 为 stage-entry build/reuse 与 stage-close/submit-preview fresh read 提供同一权威 seam；Gate 只见 `ReportingGateTruth`，不见 actor/path/artifact/finalizer。production `reporting_build_validated_revision` 不再有无-authority fallback：它从 operation 服务端读取 active project、sealed snapshot、frozen canonical path 与 exact root unit组成 `ReportingProjectAuthority`，build/reuse 全程使用 `PgReportTruthPort::with_project_authority`，validated revision persist transaction 再锁定并逐字段复核；retired/pre-entry rebind/build 后 rebind 均不能落 report。bundle/current source/integrity/frozen org/Cleanup 全部从一个 `REPEATABLE READ READ ONLY` transaction 读取，不能把两个并发失败状态拼成从未存在的 PASS；stored claim hash、same-operation evidence、complete current manifest 与 Cleanup residual 任一缺失/错误都 fail closed。

- `tracking_bridge::PgChainPersistence` 的 exact chain load 必须同时按 `id + session_id + agent` 过滤，不能把 model-visible UUID 当资源授权；chain body update 必须检查 `rows_affected == 1`，0-row update 不能伪装为 durable success 或生成 resume marker。
- `tracking_bridge::PgChainPersistence` 的 bound-worker load/checkpoint 必须调用 `RuntimeMemoryRepository::load_bound_worker_chain/checkpoint_bound_worker_chain`；不得先 raw `message_chains` update 再 worker checkpoint。load 还要验证 running、未过期、token/epoch/version；stage specialist 以 server-owned DB `AgentType` 映射（company_stage_controller/recon/prober/enumerator/vuln_scanner/attack_analyst/candidate_verifier/pentester→pentester）持久化，并与DB exact-resume ownership join保持同一closed mapping。
- `tracking_bridge` 写 legacy `agent_logs.agent_type` 时要保留旧 enum 兼容：`prober` / `enumerator` 原样写入，新的 precise runtime roles `vuln_scanner` / `attack_analyst` / `candidate_verifier` 只在这一张 legacy telemetry 表折叠为 `pentester`。Runtime Memory、Team UI 和 stage identity 仍保留精确 role，不得为了 telemetry enum 改掉业务身份。
- V2 `submit_stage_deliverable` 把 durable submission id 放进当前工具结果和 typed captured sink；不得同时写 shared legacy last-deliverable slot。stage_run 只按本 worker result id reload canonical payload，避免前一个 org 的 residue 被下一 org 误用。
- `ai_get_stage_team_read_model` 必须先用 exact operation/execution tuple 验 execution 归属，再在同一 snapshot 读取所有 Team 子表。lease token/owner/expiry、checkpoint body、active tool 的名称/参数/结果、raw canonical output、dynamic-request budget/body 均不能越过 IPC；只允许为人工恢复返回非敏感的 `row_version`、`checkpoint_version` 与 active-tool lifecycle record id。`ai_resolve_stage_team_recovery` 只能由 server 解析出的 LocalDesktop operator 调用，并以这些 exact CAS 字段把 unknown external action 关闭为 blocked；它不得重放工具。trace pointer 只能触发 refresh，不能成为 scheduler truth。

## 注意事项 / 坑

- 各 bridge 是**依赖倒置的实现侧**：agent-kit 定义 trait（`db_traits`），这里用 golish-db 等实现并注入——别把 golish-db 依赖塞回 agent-kit。
- authoritative `knowledge_graph_*` IPC 不接收 actor id/project path；legacy `kg_*` 仍保留兼容但不进入 scoped temporal truth。
- `TrustedAuthorizationContext` 只可由 memory-app loader 结合本层 DB snapshot + server policy 生成；`ContextSubject` 只是待校验 identity。外部 embedding 默认关闭，Graph/context 查询失败只能显式 degrade/fail，不能回退 global memories/wiki。
- `knowledge_memory.rs` 的 assertion-promoter 对 `StageEpisodeClosed.v1` / `PostExploitActionPrepared.v1` 从 persisted canonical rows/evidence 派生；对 Candidate terminal、Post-Exploit foothold/objective terminal、Cleanup terminal 从 immutable event envelope/source + deny-unknown structured payload 派生。所有 scoped identity 取 envelope + sealed frozen snapshot，payload 无权覆盖 operation/project/org/source；crash-before-ack 重放必须保持单 Assertion/Document/Embedding/graph lineage 版本。Candidate terminal event 中仅 `blocked + blocker_reason_code + evidence_ids=[] + fact_delta_count=0` 可 intentional suppression；该事件仍只发布 aggregate `fact_delta_count`，因此 count>0 不得从 evidence union 猜 FactDelta role。
- `FactDeltaAccepted.v1` 现在只由 `attack_wave_consolidations` 在 accepted transition 的同一事务中，从 typed FactDelta decision/evidence 写 Assertion、event 与四路 delivery；bridge/projector 只消费该已存在 Assertion 的原子 promotion seam。裸 event、未绑定 decision 或证据漂移仍 fail closed，不能用 `succeeded_suppressed` 假装投影成功。Source invalidation 是 producer-preclosed 特例，Reporting final event 保持 empty route。
- Cleanup submit preview 与 main/org stage-close Gate 都只消费 `CleanupCloseoutPort` 权威计数；repo 缺失、identity 缺失、open/missing obligation、undisclosed residual 或 relationally-invalid terminal status 一律 BLOCK。
- `commands/core/chat.rs` 的 TaskMode upsert `sessions.chat_session_key` 后，必须把返回的 durable UUID 绑定到 live bridge 的共享 tracker identity，再创建/运行 `BridgeAgentExecutor`。绑定失败应在首个 stage tool 前 fail closed；不能让 orchestrator/gate 查 durable session、tool lifecycle 却写随机 session。
- Task/Profile GUI 与 headless stage-run 不得各自重建上述 setup。fresh full-profile、fresh stage slice 与 exact resume 都必须先经过 `task_operation::prepare_task_operation`；workspace authorization 只能从 configured `AgentBridge.workspace()` canonicalize，adapter 不能另传一个不同路径。setup/authorization/operation 任一步失败都要由 `PreparedTaskOperation::finish` 清理 request-local state。
- `db_bridge/recon.rs` 的所有 org-keyed target/asset/evidence read 在 `organization_id=None` 时返回空/拒绝，不能把 NULL 解释成全库 axis；Some(org) 只可读 exact org/subtree。否则同一持久 DB 的旧测试资产会污染新 GUI/CLI operation。
- `db_bridge/recon.rs::scoping_target_snapshot` 只投影 trusted pre-stage intake：`customer_provided` 与 manual/imported/stage-run-seed/seed/cli 同属可信层，discovered/provider-derived 来源不得升级成授权根。snapshot 为空是合法 organization-only Scoping，不要求空 `scope_review`；非空才要求本轮全部 persisted lifecycle 中 exactly one exact review，不能 latest-only 覆盖早先编辑。
- `GolishDbRepoProvider` 的 Scoping passive recon authorization 只薄委托给 `golish-db::operation_scope_decisions`：它不在 app 层信任模型 UUID，也不复制 lifecycle SQL。该 seam 仅允许 exact operation/scoping execution/project root 的 latest same-root human choice 为 included 时，把 pre-freeze subsidiary discovery 绑定到根组织；默认/test double 仍 fail closed。
- `db_bridge/recon.rs` 的 active-recon scope review 是 TargetIntel→EAS 的原子授权 seam：candidate read 必须 exact operation/org/current_stage，并要求本阶段 window 内确有 refreshed `asset_intel` row；展示集合是该 org 当前全部 trusted + asset-intel `scope=in` exact target，避免历史 target 躲在表外却进入 EAS。apply 在 operation `FOR UPDATE` 锁内重读并 exact-match presented，selected 只能是原样非空子集；selected provider source 升为 `customer_provided`，unselected 变 `scope=out`，同事务写 state_blob marker 与 audit。resume 只在 marker operation/org 与当前 trusted in-scope set exact-match 时授权；无 migration，也不读取 `active_discovered`。
- `db_bridge::scoping_actions_for_session` 必须把 orchestrator 解析出的 trusted root UUID 继续传给 `golish-db`；不能只按 session/time window 聚合。Parent-only decision、candidate proposal 与 unit review 均以该 org 为轴，included branch 还必须保持 proposal→approved review 顺序。
- checkpoint/cursor reset 必须调用 `runtime_memory_tx::supersede_stage_checkpoint`：按operation cursor CAS，在一个transaction内以exact lease/epoch核对active pointer；running/received external tool必须在任何mutation前拒绝，不能仅terminalize DB row后让迟到landing写回facts。没有active writer时才supersede受影响Unit/Worker、invalidate handoff、替换active execution、重建selected stage plan-first Unit并同步frozen-contract state/graph/cursor。V2Only必须忽略caller `next_state_blob`，从locked persisted blob剥离legacy checkpoint与affected stage-owned namespace，只保留server sibling并写reset marker。不能只改`state_blob`留下可claim的stale V2 row，也不能删除runtime/evidence history。显式`restart_from_stage_purge`还必须在该同一transaction内以sealed frozen organization units清mutable Company facts；run-owned rows再按current operation + Task session aliases过滤，ownership不足的Target catalog/Finding/Vuln history保留，重叠frozen scope的active operation在mutation前拒绝。
- `db_bridge/recon.rs` 实现 `org_subtree_units` 时走 `golish_db::repo::organizations::subtree`，供 root-bound `stage_run` 读取完整 DB organization tree；这条路径不要降级成仅信任工具参数里的 `orgs`。
- `query_target_data` 的 enumeration 读模型支持 `sections=["directories","coverage","web_roots"]`：`directories` 读 target-bound `directory_entries`；`web_roots` 只返回 target URL、confirmed-open `ports[].url` 或明确 HTTP(S) service metadata 可确定的 exact `scheme://host:port/`，去掉 path/query；closed/filtered port、unknown TCP（即使是 80/443/8080）与仅有 host-level HTTP metadata 的行不得猜 origin。`coverage` 仅保留 legacy business observation，固定 `authoritative=false`，不得把 `directory_entries` / `api_endpoints` 的 host-level found 当 completion；authoritative completion 只看 `stage_worklist_status` / `check_stage_asset_coverage` 的 fresh exact-origin outcomes。

`coverage_truth`，checked_empty/error/blocked/not_applicable 来自 `technique_outcomes` + `source_query_log` terminal rows + 同 session `audit_log` evidence facts，适用性必须和 gate 一样用 `AssetClass::classify(Some(target_type), value)` 的 value-aware 口径，不能只看 `targets.type`；URL 形态值即使存成 `domain` 也不能冒出假的 PORT/SERVICE pending。EAS LIVENESS lookup 使用 endpoint key（保留 URL failed to resolve、no targets specified）在 UI read-model 显示为 `checked_empty`，不把可解释的终态负结果画成 generic error。EAS 中若 PORT 已经 terminal `checked_empty/not_applicable`，read-model 会把仍 pending 的 `next_action`，避免模型在看不到前端覆盖表时盲交；worker objective 必须把它当作 `submit_stage_deliverable` 前的 mandatory self-check，而不是提交失败后的修复提示。开启 `asset_wave_barrier` 的 stage 优先按当前 running `stage_asset_waves.asset_values`
